How an agent makes a level

The world is text

A level is described in ordinary text files. The agent reads and edits them like code, and the engine points out mistakes right away.

A check in a second

The agent runs the game without a window and learns in a fraction of a second what happened: where the ball rolled, what fell, whether the character made it.

Full determinism

The same input gives the same state and the same events in the same order wherever the game runs. If a test passed for the agent, players get the same result.

The Report button

If a jump falls short or a crate gets stuck, press Report in the editor and add a few words. The agent gets that moment, runs the game from it and works out what to fix.

What the engine does today

Editor
Play, pause and step through the game. An agent's edits appear in the open editor right away.
Graphics
Up to 256 lights in a frame, soft shadows, water, grass in the wind, and marks and signs on surfaces.
Scripts
Game logic is written in TypeScript. A script can change while the game is running.
Animation
Models and characters from Blender and other tools, with animation and smooth blends between moves.
Game UI
Menus and on-screen hints are laid out like an ordinary web page.
Stories
Dialogues with choices, and cutscenes with camera moves and animation.
Audio
Sounds on objects and in zones: louder up close, quieter far away.
Navigation
When a level loads, the engine works out where characters can walk.
Physics
Things fall, roll and collide. A character runs on a keyboard or a gamepad, and the jump forgives a slightly late press.

Questions

Which agents does SDE work with?
Any agent that can run commands in a terminal: Claude Code, Codex, Cursor and others. The agent drives the engine with plain commands.
Is it built on Unity or Godot?
No, it is an engine of its own.
What is the engine written in?
C++: physics, graphics, animation, audio and the editor. The agent writes game logic in TypeScript: agents write it best, and many mistakes show up before the game starts. Scripts run in a small built-in interpreter, as in many big engines. Physics and rendering never go through scripts: a script gets events and sends commands.
Where will games run?
On desktop and in the browser. Phones come later. No consoles yet.

Phase 1 is closed: the audit and the first game on SDE

29 October

The Phase 1 cut went through an audit. Five checks by agents and an independent review found 25 bugs, three of them critical: a script memory leak stopped the world after 15 seconds of heavy fire, headshots did not count on bots spawned from templates, and animation events went silent after a rewind. All are fixed, and the engine is tagged stable.

A long run of 60,000 ticks matches bit for bit between the native build and the browser.

Landslide now runs on SDE. Agents ported it one to one, with tests that check every number against the original. Next the game grows: a collapse into debris, seven biomes, a ghost of your best run. Over the Edge and Sky Lantern move to SDE next.

By the evening much of it is in the game. The collapse breaks the world apart: platforms crumble into tumbling debris, and cracks run ahead of the edge. Seven biomes are in: meadow, hills, canyon, glacier, cave, volcano and valley, each with its own light and backdrop. Surfaces matter now: ice never holds the wedge, wood holds it on any face, crystal bounces it back. Landings shake the camera, a hard hit freezes the action for an instant, and a jump after a fall starts a new run at once.
